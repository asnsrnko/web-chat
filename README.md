# Web Chat

Учебный веб-чат в реальном времени на WebSocket.

## Что умеет

- регистрация и вход по нику и паролю;
- общий чат с мгновенной доставкой сообщений;
- история из PostgreSQL (сначала последние 100, дальше можно подгрузить старые);
- список кто сейчас онлайн;
- системные сообщения «вошёл / вышел».

## Стек

- Frontend: React (Vite), CSS
- Backend: Node.js, Express, библиотека `ws`
- Авторизация: bcryptjs (хеш пароля), JWT
- База данных: PostgreSQL

## Как запустить

Нужны Node.js и PostgreSQL. Ещё понадобятся два терминала — один для сервера, второй для клиента.

### Сначала база

Проверьте, что PostgreSQL запущен. Потом один раз создай базу:

```bash
createdb webchat
```

В папке `server` есть файл `.env` с настройками подключения. Если его нет — скопируйте из `.env.example`. Обычно там что-то такое:

```
DATABASE_URL=postgresql://localhost:5432/webchat
JWT_SECRET=webchat-student-secret-change-me
```

Таблицы `users` и `messages` создаются автоматически при старте сервера.

## Как запустить

Нужны Node.js, PostgreSQL и два терминала.

### 1. Сервер

```bash
cd server
npm install
npm run dev
```

Сервер: `http://localhost:3001`, WebSocket: `ws://localhost:3001`.

### Клиент

В другом терминале:

```bash
cd client
npm install
npm run dev
```

Откройте `http://localhost:5173`.

Сначала создайте аккаунт на вкладке «Регистрация», потом можно выйти и войти снова по нику и паролю. Для проверки чата откройте две вкладки с разными аккаунтами.

## Как устроено

Проект делится на две части: `client` (то, что в браузере) и `server` (то, что отвечает на запросы и держит сокеты). Сообщения и аккаунты лежат в PostgreSQL.

### Аккаунты

Когда человек регистрируется или входит, клиент стучится на обычный HTTP:

- `/api/register` — создать аккаунт
- `/api/login` — войти

Пароль в базу как есть не пишется — сначала хешируется. Если всё прошло нормально, сервер отдаёт токен. Клиент кладёт его в `localStorage`, чтобы после обновления страницы не пришлось логиниться заново. Кнопка «Выйти» просто удаляет этот токен.

### Сам чат

Чат работает через WebSocket. После входа браузер подключается к серверу и отправляет что-то вроде «вот мой токен, пусти в чат». Сервер проверяет токен и:

1. присылает последние сообщения из базы;
2. присылает список тех, кто сейчас онлайн;
3. если человек зашёл не во вторую вкладку, а реально «новый» — пишет всем системное сообщение, что он вошёл.

Когда кто-то пишет в чат, сообщение сначала сохраняется в БД, а потом сервер рассылает его всем подключённым. Поэтому у остальных оно появляется сразу, без обновления страницы.

Если пролистать историю вверх, клиент просит ещё более старые сообщения, и сервер докидывает следующую порцию из базы.

Когда вкладку закрывают или нажимают «Выйти», соединение рвётся. Если у этого ника больше нет открытых вкладок, остальным уходит «вышел из чата», и список онлайн обновляется.

## Бизнес-ценность

### Зачем нужен такой чат

Простой общий чат полезен там, где людям нужно быстро обмениваться короткими сообщениями:

- внутренняя поддержка пользователей продукта;
- обсуждение задач в небольшой команде;
- онлайн-консультации;
- учебные и демо-стенды с real-time.


### Как развивать дальше

1. Комнаты / приватные диалоги — не один общий поток.
2. Восстановление пароля и более строгая политика паролей.
3. Вложения — файлы, скриншоты, ссылки на документы.
4. Уведомления — если пользователь не в чате.
5. Модерация — жалобы, блокировки, аудит.
6. Масштабирование — несколько инстансов сервера + Redis.
